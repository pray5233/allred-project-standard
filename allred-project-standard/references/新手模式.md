# 新手模式

Use this reference when the user explicitly requests beginner mode with `allred新手新项目`, `allred新手项目`, `新手项目`, `新手模式`, or when the current project is already recorded as beginner mode.

The goal is to help a beginner start and continue a useful project without being blocked by development terms, environment setup, app-versus-web decisions, debugging language, or acceptance jargon.

Beginner mode is a communication layer across all project stages. It lowers the interaction burden, not the engineering standard.

## Trigger Guard

Do not activate beginner mode just because the word `新手` appears in ordinary content.

Do not treat these as beginner-mode requests unless the user also says they want beginner mode:

- `新手培训`
- `新手员工`
- `给新手使用`
- `新手教程`
- `新手说明`
- file names, document titles, screenshots, or quoted text containing `新手`

If unclear, ask:

```text
这里的“新手”是指使用者是新手，还是希望我用新手模式推进？
1. 使用者是新手，但我仍按标准模式推进（推荐）
2. 请用新手模式推进
3. 两者都是

请回复数字，也可以直接说明。
```

## Persistence And Exit

If a project starts in beginner mode, keep beginner interaction for later stages:

- function debugging
- new feature requests
- UI optimization
- acceptance and review
- handoff or next-step planning

Do not restart the new-project workflow just because beginner mode is active.

Exit beginner mode when the user says:

- `退出新手模式`
- `切换标准模式`
- `不用新手模式`
- `按标准流程`
- `按标准模式`
- `我已经熟悉了`
- `用专业模式`

When exiting, say:

```text
已切换为标准模式。我会继续处理当前阶段，不重新启动项目。
```

Then continue with the current project stage using the standard Allred workflow.

## Defaults

Use these defaults unless the user says otherwise:

- project level: small project candidate
- development strategy: directly implement all clear, low-risk functions in the current scope
- runtime environment: normal office computer
- delivery mode: no-install or low-install file tool
- requirement sorting method: lightweight sorting
- validation: sample input, expected output, original-file protection, target-user environment

Do not assume the user has Python, Node.js, Git, terminal experience, admin permission, or a local server.

## First Response

Start with a calm, compact response. If the user has already described the rough need, first summarize that need and ask only the next missing decision. Do not restart by asking a generic category question.

If the user only gives a beginner trigger without a project description, use:

```text
我会按新手模式启动，先不讲复杂技术，也不直接写代码。
默认按普通办公电脑考虑：尽量做成不用安装、能双击或用浏览器/Office 打开的工具。

先确认这个工具主要处理什么？如果有样例表格、截图、旧模板或以前手工整理过的文件，后面建议先放到当前工程里，我会先看资料再问问题。

1. 表格/Excel/CSV 整理（推荐）
2. 文件整理、改名、归档
3. 查询、目录、知识库
4. 小软件界面
5. 其他，我直接描述

请回复数字，也可以直接写自定义内容。
```

If the user has already described the project, use:

```text
我会按新手模式启动，先不讲复杂技术，也不直接写代码。
我先理解为：你想做一个____工具，主要处理____，希望得到____。

下一步只补一个关键问题：____？
1. ____（推荐）
2. ____
3. ____

请回复数字，也可以直接写自定义内容。
```

## Beginner Flow

Ask one question at a time.

If the beginner says `停止追问`, `够了`, `先总结`, `进入计划`, `按当前理解推进`, or similar wording, stop asking new questions. Summarize the current understanding in plain language, list assumptions, and ask whether to enter the pre-development functional restatement.

Use this order:

1. what the tool processes
2. whether sample files, screenshots, old templates, or manual examples can be added to the workspace
3. what input the user has
4. what output the user wants
5. what the user's computer can open
6. what functions are clear enough to build in the current scope
7. how the user will verify success

Do not show the full project startup card at the beginning.

Do not ask about frameworks, databases, servers, command line, Python, Node.js, Git, or deployment unless the user's answer makes them necessary.

## Ongoing Stage Adaptation

Use the same stage routing as standard mode, but change the visible questions.

### Beginner Function Debugging

Use when the user reports wrong results, errors, a button not working, import/export problems, or "不会用".

Ask one simple question first:

```text
我先按新手调试方式处理，不直接改代码。
先确认你看到的问题是哪一种？
1. 操作后结果不对（推荐）
2. 页面或工具打不开
3. 按钮点了没反应
4. 导入/导出文件不对
5. 我直接描述现象

请回复数字，也可以发截图、样例文件或直接描述。
```

Prefer screenshots, sample files, actual output, expected output, and the user's operation path over technical terms like logs, stack trace, or reproduction protocol. Codex should inspect files and errors when available.

### Beginner New Feature

Use when the user says "再加一个", "能不能支持", "我还想要".

Ask:

```text
这是想新增功能。我先不直接加，先判断要不要放进本轮。
1. 先记到后续功能，当前版本先稳定（推荐）
2. 本轮必须加进去
3. 先只讨论，不开发
4. 这个其实是现在功能没做好

请回复数字，也可以直接说明。
```

If the user chooses current round, restate the new function in plain language and ask for confirmation before implementation.

### Beginner UI Optimization

Use when the user says "不好看", "不会用", "按钮乱", "看不懂".

Ask:

```text
我先按新手界面优化处理，不直接重做整个界面。
你最想改善哪一步？
1. 不知道先点哪里（推荐）
2. 按钮或文字看不懂
3. 页面太乱
4. 手机/小屏幕显示不对
5. 我直接描述

请回复数字，也可以发截图。
```

Focus on the main user action, clearer labels, fewer steps, and visible feedback. Do not redesign from scratch unless the user confirms.

### Beginner Acceptance And Review

Use when the user says "做好了", "验收", "下一步", "能用了".

Classify feedback in plain language:

```text
我先把反馈分一下类：
1. 没达到原来承诺，需要修（推荐）
2. 能用但不顺手，需要优化
3. 想加新功能
4. 这个功能不想要了
5. 暂停，先整理说明

请回复数字，也可以直接说具体问题。
```

Beginner-mode acceptance still requires the target user to open it, process a sample input, understand the output, and avoid damaging original files.

## Beginner Questions

### Materials

```text
有没有可以参考的样例资料？
1. 有，我可以把样例文件/截图/旧模板放进当前工程（推荐）
2. 暂时没有，先按我的描述做一个小版本
3. 我先说明资料在哪里或长什么样

请回复数字，也可以直接写自定义说明。
```

### Input

```text
你的输入材料是什么？
1. 一个 Excel/CSV 文件（推荐）
2. 一个文件夹里的多个文件
3. 一批文档或资料
4. 还不确定，我需要先整理样例

请回复数字，也可以直接写自定义输入。
```

### Output

```text
你希望工具输出什么？
1. 一个整理好的 Excel/CSV 文件（推荐）
2. 一个新文件夹或文件清单
3. 一个可以查看的页面/报告
4. 一个可反复打开的小工具

请回复数字，也可以直接写自定义输出。
```

### Runtime Environment

```text
使用者电脑一般能打开什么？
1. 浏览器和 Office（推荐）
2. 像普通软件一样双击打开
3. 只能打开普通文件，不能安装软件
4. 可以运行开发工具或命令行

请回复数字，也可以直接写自定义情况。
```

### Delivery Mode

```text
本轮先做成哪种最容易用的形式？
1. 免安装文件工具/单 HTML/Excel 模板（推荐）
2. 桌面 App/可执行文件
3. 网页版工具
4. 脚本工具，后续再包装

请回复数字，也可以直接写自定义形式。
```

### Current Scope

```text
本轮开发范围怎么定？
1. 直接做完已经明确的功能（推荐）
2. 先做最小可用功能，后续再加
3. 先只整理方案，不开发

请回复数字，也可以直接写自定义范围。
```

## Beginner Output Format

After the necessary questions are answered, output only:

```text
新手模式：
项目级别：
使用者电脑环境：
交付形态：
输入：
输出：
本轮开发范围：
暂不处理：
验收方式：
开发前功能复述：
是否确认开始：
```

Then ask:

```text
开始做之前，我先用普通话复述一遍：
这个工具给____使用，输入____，本轮做____，输出____，暂不做____，用____验收。

请确认功能是否有改动或遗漏：
1. 没有改动，开始做（推荐）
2. 有遗漏，需要新增一个功能
3. 有多余，需要先删减或后移
4. 我直接说明要改哪里

请回复数字，也可以直接写自定义调整。
```

## Escalation Rules

Leave beginner mode and explain why when:

- multiple departments or many users must share the same data
- accounts, permissions, audit, database, or hosted web service is needed
- real devices, production systems, or shared business systems are involved
- data sensitivity, customer commitment, or safety risk appears
- the user asks for long-term maintenance, packaging, automatic update, or deployment

Use this wording:

```text
这个需求已经超出新手轻量模式。建议升级为标准项目流程，因为它涉及多人/系统/权限/维护等风险。
1. 升级为标准流程（推荐）
2. 仍按新手模式先做一个不联网、不写系统的本地版本
3. 暂停，先整理需求

请回复数字，也可以直接写自定义选择。
```

## Validation

Beginner-mode delivery is not complete until:

- the user can open it on the expected computer
- sample input can be processed
- output is understandable
- original files are not damaged
- usage steps are short enough for a non-developer
