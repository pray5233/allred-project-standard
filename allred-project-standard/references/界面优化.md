# 界面优化

Use when behavior is substantially correct and the goal is clarity, speed, accessibility, layout, or visual quality. Shared workflow comes from `references/核心执行流程.md`.

## Inspect Before Designing

Open or render the current interface. Inspect the actual target flow, screenshots, states, responsive behavior, existing design system, and implementation constraints. Do not redesign from a text description when the current UI can be viewed.

Define the user outcome:

- which workflow should become clearer or faster
- which confusion, error, density, hierarchy, or accessibility problem is observed
- what must remain behaviorally unchanged
- which viewports and states require evidence

Use a comparable local/design-system benchmark first. External visual inspiration is useful only when it matches the domain, workflow, density, and technology path.

## User Gate

Focused corrections inside an explicit target need no extra confirmation. Ask one decision only when alternatives change information architecture, workflow, brand direction, density, or visible product behavior.

## Execute And Verify

- make focused changes; do not replace the whole interface without scope evidence
- preserve data behavior and keyboard/accessibility contracts
- render desktop and mobile states when relevant
- verify loading, empty, error, long-text, and interaction states
- use screenshots and interaction evidence for visual claims

Report the target flow, changed design decisions, rendered verification, behavior regressions checked, and remaining visual gaps.
