# 长期任务模式

Use this reference when the user explicitly starts or continues a long-running task, or when the active project is already recorded as a long-term task.

Long-term task mode is for projects that span multiple rounds, depend on evidence, or need accumulated conclusions. Examples include equipment troubleshooting, measurement stability analysis, data/log analysis, technical documentation, knowledge-base building, staged process improvement, and long-running app/tool development.

## Trigger Words

Use long-term task mode when the user says:

```text
allred长期任务
长期任务启动
开始长期任务
继续长期任务
长期任务复盘
长期任务调试
长期任务资料分析
长期任务验证
```

If the user only says `长期任务` and intent is unclear, ask:

```text
这里的“长期任务”是希望进入 Allred 长期任务模式，还是只是在讨论长期任务？
1. 进入长期任务模式，并建立或继续本轮推进（推荐）。
2. 只是讨论长期任务方法，不进入流程。
3. 先做长期任务复盘，再决定下一轮。

请回复数字，也可以直接写自定义安排。
```

Do not trigger long-term task mode only because a document title, training topic, or quoted text contains `长期任务`.

## Core Rule

Long-term tasks must preserve the distinction between:

- confirmed conclusion
- unverified assumption
- current-round objective
- future task
- removed or rejected direction

Never turn a hypothesis into a conclusion just because it appeared in a previous conversation.

## First Start

When the user starts a long-term task but has not described the background, ask for a rough description first:

```text
我会按 Allred 长期任务模式启动。先不直接分析结论，也不替你决定方向。

先请你用一两句话描述这个长期任务：
目标是什么、涉及哪些资料或设备、目前卡在哪里、希望本轮得到什么结果。

可以按这个格式写：
这是一个____长期任务，目标是____，已有资料包括____，当前最大问题是____，本轮希望得到____。
```

After a rough description exists, ask for materials:

```text
长期任务开始前，建议先把相关资料加入当前工程，或说明资料位置。
1. 历史记录、测试数据、日志、截图或报告（推荐）
2. 设备/系统说明、接口文档、操作流程或旧工具
3. 以前的结论、会议纪要、问题清单或人工记录
4. 暂时没有资料：先按描述建立假设，并缩小本轮目标

请回复数字，也可以直接说明资料位置。
```

## Review Gate

Every long-term task round starts with a review gate.

Use lightweight review when:

- the same conversation is continuing
- previous conclusions are visible
- no major new material was added
- the user only wants the next small step

Use full review when:

- this is a new conversation
- the task has been paused for a while
- new files, logs, screenshots, reports, or device records were added
- previous conclusions conflict
- the next step may affect a final conclusion, shared tracker, device, system, or handoff record
- the user says `回顾`, `复盘`, `总结一下`, `重新梳理`, or `交接`

## Lightweight Review

Use this before normal continuation:

```text
先做轻量回顾，避免本轮跑偏：
1. 上轮已经确认：
2. 上轮尚未验证：
3. 当前最大问题：
4. 本轮只解决：
5. 本轮完成标准：

请确认是否正确：
1. 正确，继续确认本轮计划（推荐）。
2. 有遗漏，我补充一项。
3. 有错误，需要先纠正回顾。
4. 先做完整回顾。

请回复数字，也可以直接写需要调整的内容。
```

## Full Review

Use this when context is missing, evidence changed, conclusions conflict, or handoff is needed:

```text
长期任务完整回顾：
1. 项目目标：
2. 当前阶段：
3. 已有资料：
4. 新增资料：
5. 已确认结论：
6. 未验证假设：
7. 已排除方向：
8. 当前最大问题：
9. 风险和写入边界：
10. 本轮建议目标：
11. 本轮建议成果形态：
12. 本轮建议验证方式：

请确认回顾是否准确：
1. 准确，进入本轮目标确认（推荐）。
2. 有遗漏，我补充资料或结论。
3. 有错误，需要先纠正。
4. 只保存回顾，暂不推进下一轮。

请回复数字，也可以直接写需要调整的内容。
```

Use `templates/长期任务回顾卡.md` when saving or presenting the review.

## Current-Round Flow

After the review gate, execute the round in this order:

```text
1. 判断本轮类型
-> 2. 明确本轮目标
-> 3. 明确本轮不做
-> 4. 明确成果形态
-> 5. 明确证据等级和验证方式
-> 6. 明确写入边界
-> 7. 检查已有能力 / find-skills
-> 8. 执行前复述本轮任务
-> 9. 用户确认
-> 10. 小步执行
-> 11. 验证
-> 12. 本轮复盘并更新下一轮
```

Ask for the round type when unclear:

```text
这轮长期任务更像哪一类？
1. 资料分析（推荐）：先整理文件、日志、数据或历史结论。
2. 问题定位：围绕异常现象找证据和可能原因。
3. 方案制定：先形成下一步方案、检查点和风险边界。
4. 离线验证：用样例数据、历史数据或模拟方式验证。
5. 现场/实机验证：涉及真实设备、真实系统或真实流程，需要更严格边界。
6. 本轮复盘/交接：整理已完成、未验证、下一轮和交接材料。

请回复数字，也可以直接写自定义类型。
```

## Result Forms

For long-term tasks, `交付/成果形态` may be:

- analysis conclusion
- test record
- validation report
- log archive
- problem list
- knowledge index
- stage plan
- handoff note
- runnable tool or app

Choose the lowest-risk result form that can prove the current-round objective.

## Current-Round Restatement

Before any execution, restate:

```text
执行前我先复述本轮长期任务：
1. 长期任务名称：
2. 已确认结论：
3. 仍未验证的假设：
4. 本轮目标：
5. 本轮不做：
6. 输入资料/证据：
7. 成果形态：
8. 验证方式：
9. 写入边界：
10. 完成后如何复盘：

请确认本轮任务是否有改动或遗漏：
1. 没有改动，按以上内容开始执行（推荐）。
2. 有遗漏，需要新增一个本轮必须任务。
3. 有多余，需要删减或后移某些任务。
4. 表述不准确，我直接修改说明。

请回复数字，也可以直接写需要修改的内容。
```

Wait for confirmation before executing.

## Example Prompts

Start:

```text
allred长期任务
这是关节臂测量机长期任务，目标是提升测量稳定性和问题定位效率。
相关资料我会放到当前工程里。
请先帮我建立长期任务推进流程。
```

Continue:

```text
继续长期任务
项目：关节臂测量机
本轮目标：整理最近的测试日志，判断测量误差是否稳定。
请先做轻量回顾，再确认本轮范围和验证方式。
```

Review:

```text
长期任务复盘
本轮已经完成日志整理和初步误差分析。
请区分已验证结论、未验证假设、遗留问题和下一轮建议。
```

Debug:

```text
长期任务调试
关节臂测量机最近三次测试误差波动不一致。
请先整理现象和证据，不要直接给最终原因。
```
