# 首次触发示例

Use this reference only when the first response style is unclear. Follow `references/交互与确认规则.md`.

## Trigger Only

User:

```text
allred新项目
```

Response shape:

```text
我会按 Allred 项目流程启动。先请你用一两句话描述：
- 想做什么
- 给谁使用
- 现在的输入或做法
- 希望得到什么结果

暂时不用决定技术方案。
```

## Bounded Office Tool

User:

```text
allred新项目
我想做一个 Excel 清单整理工具。
```

Response shape:

```text
我理解你想做一个把 Excel 清单整理成固定输出的工具。

开始前请把已有依据一起告诉我：
1. 有样例 Excel、旧输出或字段规则（推荐）。
2. 我已经想过工具应该怎样处理，我先说明。
3. 两者都有。
4. 现在没有文件，我先补充希望怎样处理和输出。

请回复数字，也可以直接发资料位置或写出想法。
```

After inspection, Codex drafts the project brief, evidence-based level, recommended current-round strategy, and only the decisions that affect scope or delivery. Do not ask a separate vague level question.

## Data-Dependent Online Tool

User:

```text
allred新手项目
我想做一个自动搜索行业公开动态的 App，目前没有整理资料。
```

Response shape:

```text
我理解你想做一个自动收集并查看行业公开动态的 App。

为了先把方向弄准，请一次补充还没有说明的内容：
1. 主要给谁使用，现在怎样找和整理这些信息，最麻烦的是什么。
2. 虽然资料还没归拢，是否已有关注对象、参考网站、旧表格、截图或人工做法；有位置就直接发，没有也可以说明。
3. 你已经想到的第一版做法、必须有的内容和明确不想做的内容。
4. 做到什么样，你会认为第一版可以使用。

可以按顺序回答，也可以直接用一段话说明。
```

This is the same new-project intake used by standard expression. Do not turn missing materials into a real-source/simulation/plan menu, choose simulated data silently, or start framework/toolchain work before evidence and product decisions are ready. If evidence later proves several genuinely different validation routes, compare their user-visible consequences in one decision packet.

## Consequential Project

User:

```text
allred新项目
我想做一个连接真实设备并生成检测结论的软件。
```

Response shape:

```text
我理解这是一个连接真实设备并形成检测结论的项目。设备边界、结论证据和回退方式会直接影响开发路线。

请先提供或说明：设备文档、历史测试数据、接口/日志、旧工具、人工判断规则，以及你已经考虑的初步方案。我会先只读分析，再给出项目简述、风险依据和本轮建议，不会直接操作设备。
```

Use a full review and explicit write boundary before any device/system action.
