# 资料收集与分析

Use this reference before entering requirement sorting or `grill-me` for a non-trivial new project.

The purpose is to avoid starting from oral description alone when project files, sample data, screenshots, historical forms, or process documents can answer factual questions.

Also collect the user's own first-version idea before Codex proposes a competing design. The user's existing thinking is project material too.

## When To Use

Use this step after the user has described a rough requirement and before structured requirement sorting.

Do not use it to block tiny, obvious edits. For a genuinely small project with no files needed, briefly record `暂无资料` and continue with a smaller validation scope.

If the current message already says materials are unavailable, already provides materials, or already describes the user's first idea, do not ask the same generic gate again. Carry that information forward and ask only for a missing item that changes the next decision. For data-dependent tools with no materials, the route decision itself can replace another material question.

## Material Prompt

```text
为了避免只凭口头描述开发，请尽量把相关资料加入当前工程，或说明资料所在位置。
1. 样例文件、历史表格、原始数据、旧输出结果（推荐）
2. 现有流程说明、制度文件、截图、手工操作记录
3. 参考工具、历史项目、报告样式、现有模板
4. 关注对象清单、网站/链接、品牌/客户/设备名单、资料来源
5. 我已经想过第一版方案，我先说明
6. 暂时没有资料：先记录缺口和假设，后续再确定有效验证路线

请回复数字，也可以直接说明资料位置或第一版想法。可以多选，例如 `1 5`。
```

If the user is a beginner, simplify the wording:

```text
如果有样例表格、截图、旧模板、以前手工整理过的文件，建议先放到当前工程里。
我会先看资料，再问少量必须确认的问题。

1. 我已经放了资料（推荐）
2. 我先说说自己想的第一版
3. 资料和第一版想法都有
4. 现在没有资料，我补充自己的初步想法
5. 我先说明资料在哪里

请回复数字，也可以直接写说明。
```

## Multi-Select Material Replies

If the user replies with multiple numbers, treat all selected options as meaningful.

Examples:

- `1 4` means the user has ordinary materials and a source or object list
- `1 5` means materials exist and the user also has a first-version idea
- `3 6` means the user has a benchmark or report style but no internal sample data

Do not mark material confirmation complete until every selected material-bearing option has either been inspected, requested, or explicitly deferred by the user.

Use this response:

```text
我理解你同时选择了____。这说明本项目已有可用依据。
请先把资料、链接、文件名、报告样式或第一版想法发给我；我会先分析这些内容，再继续提问。
```

## Analyze Before Asking

Track material state explicitly:

| State | What Codex may claim |
| --- | --- |
| Mentioned | the user says a material exists; contents are still unknown |
| Located | the path or source is known; contents are still unverified |
| Read | a tool returned the relevant contents or metadata |
| Compared | Codex actually checked the relevant files/results against each other |
| Verified | the observation was confirmed by an appropriate test or independent evidence |

A filename, user description, test-fixture note, previous conversation, or expected answer does not prove that Codex read the material. Do not say `已查看`, quote fields, counts, causes, screenshots, or source behavior until the corresponding read/tool event occurred. If tools are unavailable, say what remains uninspected and continue with labeled assumptions only when safe.

When files are available:

- inspect filenames, folder structure, README files, sample data, screenshots, templates, scripts, logs, and exports that relate to the project
- infer factual requirements from the materials instead of asking the user to repeat them
- distinguish file-backed facts from assumptions
- identify gaps that require user decisions
- compare the materials with the user's first-version idea when provided
- summarize the analysis before entering `grill-me` style questioning

Do not ask broad feature questions before reading clearly relevant materials already in the workspace.

## Analysis Summary Format

```text
资料分析结果：
已查看资料：
从资料中确认的事实：
仍然不确定的问题：
可能的输入：
可能的输出：
可能的边界：
用户已有第一版想法：
资料与第一版想法的匹配/冲突：
需要客户/使用者确认：
```

After this summary, ask for correction only when the interpretation changes scope or rules. Otherwise continue and combine any remaining decision with the next named project draft; do not add a material-summary approval turn.

## If No Materials

If the user has no materials:

- record `暂无资料`
- mark assumptions as unverified
- identify which missing evidence affects feasibility and which can be deferred
- choose the smallest route that can produce valid evidence
- prefer a user-supplied sample, a few real public sources, a source/rule plan, or plan-only according to the actual goal
- use mock data only when the user confirms that the purpose is to validate interaction or formatting rather than real data acquisition
- make validation stricter before claiming completion

Use this wording:

```text
当前先按暂无资料处理。我会把关键判断标为假设，不会把模拟结果当成真实能力。
下一步先选择能产生有效证据的最小路线；拿到真实资料后，再复核字段、规则、来源和异常情况。
```

## Evidence Blockers

Resolve or explicitly defer these before relying on the affected conclusion:

- the project depends on files, exports, screenshots, logs, forms, or local templates that have not been requested
- the user says files exist but their location is unclear
- Codex is about to ask questions that could be answered by already provided materials
- inferred requirements from files have not been confirmed by the user

## Record In Startup Card

Record:

```text
资料/本地文件：
已查看资料：
资料分析结论：
资料未覆盖的假设：
需要用户确认：
```
