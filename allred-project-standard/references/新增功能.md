# 新增功能

Use when the request adds behavior outside the approved current promise. Shared workflow comes from `references/核心执行流程.md`.

## Classify First

Separate:

- Bug: promised behavior does not work
- completion gap: current scope is unfinished
- new feature: genuinely new behavior
- future idea: valid but not yet selected

Fix blocking Bugs before adding dependent behavior unless the user explicitly chooses another order.

## Feature Contract

Inspect current requirements, source, tests, data/schema, UI flow, dependencies, delivery, and acceptance. Define:

- user and problem
- visible behavior and failure states
- whether it belongs in the current round or roadmap
- compatibility and migration impact
- write/security/privacy boundary
- acceptance and regression checks

Use the existing project pattern first; use `references/开发依据与能力复用.md` for a real design gap.

## User Gate

No confirmation is needed for an exact feature already authorized with clear acceptance. When the feature changes product behavior, current-round priority, stored data, compatibility, cost, permission, delivery, or maintenance ownership, batch the currently knowable decisions and ask further only when dependencies or new evidence require it.

Do not silently insert a new feature into the current round merely because it is useful. Keep total product scope and current implementation scope distinct when needed.

If the user explicitly asks for read-only preflight followed by one change confirmation, do not claim the preflight is complete before actual evidence and do not ask for approval while it is still pending. After evidence, show one complete delta: unchanged baseline, exact change, affected acceptance/regression, write boundary, rollback, and user-relevant effects. End with an explicit numbered option such as `1. 批准以上改造范围，并开始改造`; a bare `1` has no start meaning unless that option was immediately visible.

## Execution And Verification

- implement the smallest coherent feature through existing conventions
- implement from the approved contract, then add or run targeted feature and regression checks according to `references/核心执行流程.md`
- verify expected behavior, error/empty states, persistence, compatibility, and target environment as applicable
- update current/future scope records only when they exist and the write is authorized

Report delivered behavior, affected files/data, fresh verification, remaining gaps, and next roadmap item.
