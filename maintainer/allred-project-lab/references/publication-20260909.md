## Changes

1. Load the lightweight cumulative-record instructions at intake, before the
   first persistent note. Preserve one current record, source qualifications,
   explicit unknowns, pending meanings and bounded delegation.
2. State material absence within the observed boundary. Record dates only from
   supplied evidence or an observed clock, and omit unnecessary dates.
3. Keep useful investigation or comparison moving when a user has not decided;
   do not simply repeat an unchanged question.
4. Validate staged installation by structure and exact file inventory/hash,
   preserving old-installation backups. Label this as installation integrity,
   not behavioral acceptance.
5. Freeze comparison workers from their prepared snapshots rather than a live
   source directory which may change during a test.
6. Make observed command status/exit metadata citable in ordered review bodies.
   Previously it appeared only in a catalog header: a reviewer could truthfully
   cite `status=failed, exit_code=1` yet fail the exact-substring validator.
   Both the catalog and indexed event now contain that same observed metadata.
   Missing fields are not invented and a start event cannot inherit a later exit.
7. Preserve the distinction between an explicitly supplied custom suite and the
   default suite. PowerShell's case-insensitive `$suitePath` assignment had
   overwritten `$SuitePath`, silently selecting all 14 cases instead of the
   declared default 10. A separate resolved path fixes this; manifests now name
   the actually selected cases. Explicit custom suites still run all their cases.
8. Return an explicit success exit code after the installation regression's
   expected negative cases. GitHub run `34256514657` passed all 19 assertions
   but inherited the deliberately rejected installer exit code. The corrected
   workflow-style call returns zero without changing those assertions.
9. Allow a separate model/effort for runtime dialogue review and citation repair,
   retaining actor settings and immutable raw reviews. The default still inherits
   the actor. Candidate reports explicitly limit the override to these runtime
   reviews; older behavior/comparison paths retain their recorded configuration.
10. Move existing progress-communication guidance from an unloaded interview
    subsection into the shared Objective loaded at intake. Remove the duplicate
    flow diagram there. This changes instruction availability, not interview
    decisions, question counts or scope/start gates.
11. R6 follow-up exposed an earlier boundary: a context-loader failure can happen
    before Objective is available. Put the existing repair-communication rule
    before the first load, and move conditional-overlay selection alongside that
    call with its actual parameter. No automatic domain inference is added.
12. Explicit inspection lists retain each relevant target, distinguishing direct
    reads from a progress note reporting another artifact. Material summaries
    preserve original qualifications instead of adding unsupported operating
    restrictions. The unchanged A03/A09/A12 cases exercise these general owners.
13. Long-term work can enter evidence directly, but the selector omitted its
    review owner at that stage. Load the existing long-term owner there and
    follow bounded local evidence references for current conclusions. Verify
    owner inclusion, exclusion from new-project context and a bounded route
    budget. This does not trigger full workspace rescans or external access.
