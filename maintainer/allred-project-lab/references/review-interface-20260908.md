## Bounded Change

- Use Ordered evidence in the normal runtime reviewer, retaining explicit Legacy
  format for diagnosis. Keep the same reviewer, substantive prompt, assertions,
  deterministic violations and strict quote/aggregate checks. Store both raw and
  resolved reviews, the evidence bundle, format and actual helper/schema hashes.
  Citation-only repair stays in the original format and cannot change judgments.
- Reuse acceptance checks the ordered helper/schema hashes, declared format and
  matching original events; reconstruct event citations from those observations
  instead of trusting a stored bundle. Stale helpers, missing/mismatched events,
  invalid references and conflicting format metadata cannot certify a pass.
- Label CLI observations as process evidence, not proof of model receipt. A
  missing-result claim cannot be disproved solely by later/complete process
  output. Fix the constructed chronology control to distinguish a false claim
  that a command did not finish from unobserved delivery of its result; preserve
  old control evidence and add an explicit unknown-reception control.
- Refine existing progress instructions in the shared entry and beginner
  expression layer. Describe findings, practical effects and useful next work.
  Do not conceal a real blocker or invent a finding to fill an update. No change
  to intake, decision order, source meanings, permission or runtime validators.
- Extend A01 coverage with A12's existing domain-neutral communication assertion.
  Preserve its original assertions, user inputs and fixtures. Compare the old
  A01 transcript under that expanded rubric separately from fresh conversations.

## Results

The wording experiment was withdrawn after both completed low-effort dialogues
still exposed internal repair mechanics. Standard now matches this turn's entire
74-file baseline. The higher-effort test keeps its frozen candidate snapshot;
its final result is reported separately, not used to erase observed failures.

Both live low-effort reviews were grounded without citation repair and correctly
reported Fail for visible diagnostic narration. The A12 review's additional
sole-gap interpretation is debatable in context; its aggregate Fail does not
validate every explanation. Keep the raw finding and the independent, clear
communication failure. The old A01 re-review with expanded progress coverage
also found that communication issue but misattributed a user quote to an
assistant response; strict grounding rejected it. That invalid report remains.

Manual state inspection also found a possible entailment gap in A01 low: the
user restricted operations to checkout/return, while the assistant marked its
previously separate actual-versus-planned date interpretation confirmed. The
reviewer accepted that inference. Keep this disagreement: valid quotation is
not semantic approval, but an ambiguous source is not automatically proof of an
unauthorized change either. A01 high's second turn additionally called the
omission of planned dates/overdue behavior user-confirmed. Calibrate this class
with explicit-choice, partial-answer, qualifier and harmless-implementation
controls before changing runtime confirmation rules. Do not add domain terms or
more user approval ceremonies to the shared workflow based on one transcript.

The high-effort dialogue completed all three turns and received a grounded Fail
without citation repair. It demonstrably closed a two-facet Q after only one
facet was answered, with no explicit remaining-facet transfer. Retaining other
open decisions did not preserve that omitted question. The review also treated
refinement of a same-axis D label as necessarily invalid and required a separate
post-write read for an ordinary saved-state progress claim; those interpretations
are not independently accepted. Judge semantic loss and the actual claim, not
ID text changes or a new mandatory read ceremony. Preserve these disagreements
alongside the clear pending-facet and communication failures.
