# Selective Source-Attribution Experiment

## Benchmark And Scope

Inspected 2026-09-08: the Lab's ordered evidence-ID adapter and frozen citation
repair, the previous isolated claim audit, the main Skill's cumulative record
guidance in `内部记录生成.md`, and the official skill-creator's forward-testing
guidance. Reuse the installed Windows CLI and PowerShell helpers; no new
dependency, model configuration, runtime route or user trigger is needed.

The bounded hypothesis was that auditing specified record statements, with
source quotes and minimally corrected records, could help maintainers distinguish
original requirements, assistant explanations, delegation and later confirmation.
This is a selective diagnostic, not a complete project review, an authorization
gate, an automatic record writer or a required call on every user reply.

## Results And Disposition

The experiment completed 28 review tasks on 14 distinct cases, totaling 44 claim
checks and 31 model calls including three citation-only repairs. Ten constructed
controls and two full historical conversations were reviewed at low effort;
after the one planned prompt correction they were reviewed again, with xhigh
checks on the historical conversations and two previously held-out controls.
The histories were unchanged A02/A14 candidate dialogues, not fresh tests of
the currently installed main Skill. Expected labels stayed frozen.

The initial and revised low-effort R01/K2 suggestions both reopened a practical
outcome as a choice between merely reading and completing/submitting a result.
The same calls correctly recovered the original outcome in K3. K2 relied on the
later user message and assistant options, rather than reconciling the original
requirement. Full source availability and valid quotes did not ensure cumulative
meaning was preserved. Xhigh removed the explicit read-only alternative, but
that observation does not establish a reliable fix for the low-effort failure.

The correction only clarified cumulative reconciliation and the distinction
between outcomes and proof arrangements. It added no scenario-specific rule.
Because the material failure remained, both implementations stay in external
test evidence. Do not promote them, change the default reviewer, add interview
gates or require users to confirm routine implementation details.

Seven checks differed from their frozen expected categories. All involved the
boundary between unsupported attribution/status and explicit contradiction;
none established a false statement as supported. Preserve each disagreement
instead of changing the oracle to improve a score. Separate classification,
source fidelity, suggested-record meaning and actual project authority.

The held-out procurement and debugging controls preserved the unchanged
deliverable and the unverified hypothesis respectively. This is narrow useful
evidence, not reliability across projects. Three initial quotations failed exact
matching; each was repaired once without changing any judgment or record text.
All final quotations were locatable. PS7 and PS5.1 passed 18 program-contract
checks; that success does not certify semantic interpretation.

## Actual Cumulative-Record Follow-Up

The next bounded experiment used the in-use main Skill, not the historical
candidate: three cases with four native turns each, followed by a fresh session
that read the final Markdown record without the old chat. A one-paragraph
isolated record-guide candidate repeated the same cases and handoff. Explicit
record requests are part of these fixtures; this does not prove spontaneous
persistence, long-context recovery or complete project quality.

All 24 turn snapshots retained the requested record. Main outcomes, explicit
changes and pending decisions survived into the six final records and their
handoffs. However, the baseline reopened a chosen deliverable together with an
unknown format, mixed speculative topics with user-owned pending matters, and
duplicated current lists. The candidate improved the deliverable wording and
removed the speculative feature list, but attributed unknown future growth to
a user who had only said historical volume was unknown. Fresh consumers carried
that unsupported attribution forward. The candidate therefore remains isolated;
there is no main Skill or default-reviewer promotion.

Automatic dialogue reviews were baseline Fail/Pass/Pass and candidate
Pass/Fail/Pass. These are not record acceptance. The candidate failure identified
an exposed internal stage name; its broader criticism of explaining ordinary
record categories was not accepted wholesale. The attribution issue was found
by source review, not that automatic result.

The original handoff fixture moved the record to a different relative path.
Preserve its six outputs, but do not count the resulting file-identity warning
as a Skill failure. Six additional read-only handoffs retained the original
relative path without changing record bytes or source dialogue. The warning
disappeared; the record-meaning defects remained. The two handoff sets are
observations of the same records, not new actor trials.
